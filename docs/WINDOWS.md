# Установка Codex и Claude на Windows: инструкция для разработчика

## Задача и источник истины

На другом компьютере Андрей использует Codex и Claude. Нужно установить одинаковые общие правила из этого Git-репозитория без переноса сессий и машинных конфигураций.

- Универсальные навыки редактируются в `skills/`, общие инструкции — в `instructions/`.
- `AGENTS.md` и `CLAUDE.md` в корне репозитория относятся к работе над самим artex-skills, а не являются шаблонами для глобальной установки.
- Правила `english`, `my-VPS`, `tdsso.ru-plagins`, `tk-ptrans` остаются в соответствующих репозиториях. В этот репозиторий они не переносятся.
- Не нужно копировать весь прежний архив правил: системные навыки, плагины и runtime следует устанавливать средствами самих инструментов.

## Новая установка

1. Установите Git, Codex и Claude, войдите в свои аккаунты. Настройте SSH-доступ к GitHub.
2. Клонируйте `git@github.com:artex131071-andrey/artex-skills.git` в любую обычную папку Windows.
3. Прочитайте шаблоны `instructions/` и навыки `skills/`.
4. В PowerShell из корня репозитория выполните `./install-windows.ps1 -WhatIf`. Этот режим не записывает файлы и резервные копии.
5. Выполните `./install-windows.ps1`. Права администратора для записи в собственный профиль обычно не нужны.
6. Перезапустите Codex и Claude, проверьте доступность навыков/команд и чтение общих инструкций. Проверяйте их в обычной пользовательской сессии, а не в этом установщике.

Выбор одного инструмента:

```powershell
.\install-windows.ps1 -Agents Codex
.\install-windows.ps1 -Agents Claude
```

Проверка на отдельном временном профиле без изменения рабочих настроек:

```powershell
$checkProfile = Join-Path $env:TEMP ('artex-skills-check-' + [guid]::NewGuid().ToString('N'))
.\install-windows.ps1 -TargetProfile $checkProfile -WhatIf
.\install-windows.ps1 -TargetProfile $checkProfile
```

Параметр `-TargetProfile` задаёт корневую папку профиля, в которую попадут `.codex`, `.claude` и резервные копии. Он не меняет профиль Windows и настройки приложений на уровне системы.

## Что именно делает установщик

| Источник | Назначение относительно выбранного профиля |
|---|---|
| `instructions/codex/AGENTS.md` | `.codex/AGENTS.md` |
| Полные каталоги `skills/<имя>/` | `.codex/skills/<имя>/` |
| `instructions/claude/CLAUDE.md` + три процесса из SKILL.md | `.claude/CLAUDE.md` |
| Текст каждого SKILL.md без YAML frontmatter | `.claude/commands/<имя>.md` |

Три процесса, встроенные в глобальный CLAUDE.md: `project-intake`, `plan-and-wait`, `docs-closeout`. Они применяются по описанным условиям; ожидание команды не обязательно для каждой задачи.

Установщик заменяет только файлы, для которых есть источники в репозитории. Сторонние навыки и команды не удаляются. Удалённые из репозитория навыки автоматически не удаляются из профиля. Изменяемые файлы сохраняются побайтово в `.artex-skills-backups/<дата-время>/`; одинаковые тексты повторно не записываются. Копирование навыков рассчитано на текстовые файлы текущего репозитория; перед добавлением бинарных ресурсов доработайте установщик.

## Существующие пользовательские настройки

Если в глобальных AGENTS.md/CLAUDE.md есть собственные дополнения, перед установкой объедините их с шаблонами `instructions/` или сохраните отдельно. Автоматического слияния нет. `config.toml`, `settings.json`, `rules/default.rules`, авторизация, модель и параметры разрешений не изменяются.

Восстановление: найдите нужный файл в `.artex-skills-backups/<дата-время>/` и скопируйте на прежнее место, сохранив относительный путь. Например, резервная `.claude/CLAUDE.md` восстанавливается в `.claude/CLAUDE.md` профиля. Перед восстановлением при необходимости сохраните и текущую версию.

## Старые junction на этом компьютере

При первом обследовании 1 ноября 2026 года 11 ссылок `.codex/skills` вели в отсутствующий `C:/Users/artex/Project/artex-skills/skills`. После восстановления репозитория по прежнему пути все 11 SKILL.md снова доступны. Само наличие ссылок не означает, что навыки сломаны сейчас.

Новый установщик не пишет через junction/символические ссылки, чтобы не изменять источник или другие каталоги. При их обнаружении он останавливается до первой записи. Для перехода на физические копии сначала проверьте тип и назначение конкретной ссылки, отдельно удалите только саму ссылку средствами Windows, сохранив целевой каталог, затем повторите установку. Не применяйте рекурсивное удаление к непроверенным путям. На чистом втором компьютере ссылки создавать не нужно.

Расположение репозитория не зашито в установщик. Если переносите сам репозиторий на этом ПК, старые junction потребуют отдельного внимания. Физические копии от нового установщика от перемещения репозитория не зависят.

## Как обновлять и передавать изменения

1. На исходном компьютере внесите изменения в `skills/` или `instructions/`.
2. Проверьте установку на временном профиле, обновите README/эту инструкцию/CHANGELOG по смыслу изменений.
3. Просмотрите `git diff`. Коммит и отправка в GitHub выполняются по команде Андрея.
4. На другом компьютере выполните `git pull --ff-only`, затем `./install-windows.ps1 -WhatIf` и `./install-windows.ps1`.
5. Перезапустите инструменты. Локальные физические копии сами по Git не обновляются.

Необходимо сохранять условный характер `plan-and-wait`. Навыки `docs-closeout` и `gh-actions-repair` имеют разные формулировки о commit/push; не используйте само завершение задачи как разрешение отправлять изменения. Учитывайте прямую задачу пользователя и её ограничения.

## Происхождение перенесённых правил

Основой послужили реальные `.codex/AGENTS.md`, `.claude/CLAUDE.md`, корневые языковые правила профиля и канонические `skills/` восстановленного репозитория. Переносимые шаблоны нормализованы: добавлен явный русский язык для Claude, описаны оба инструмента и убраны абсолютные пути к старому профилю. Три встроенных процесса Claude формируются непосредственно из актуальных SKILL.md.

Копии отсутствовавших ранее навыков восстанавливать из экспорта больше не нужно: исходники снова есть в репозитории. Остальные найденные системные навыки и конфигурации не являются правилами этого репозитория и сюда не включены.

## Проверка установщика перед изменениями

```powershell
.\tests\Install-Windows.Tests.ps1
```

Проверки создают отдельную папку в TEMP, не меняют активный профиль и оставляют тестовые файлы для просмотра. Проверяются сухой запуск, новая и повторная установка, резервная копия локальных дополнений, сохранение стороннего навыка, выбор одного инструмента и отказ от записи через junction до начала установки. Для проверки совместимости запускайте этот же файл в PowerShell 7 и Windows PowerShell 5.1.
